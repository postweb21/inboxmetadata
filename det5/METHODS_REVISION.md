# Methods revision: workflow-pattern evaluation

Workflow patterns were divided according to whether a unique hidden planted state was required for evaluation. Patterns 1, 4, 7, and 8 were treated as planted detection tasks and evaluated against generator ground truth using sensitivity, positive predictive value, and F1 score. Pattern 2 was defined directly from observable metadata as a courtesy-copy message with no access event within 14 days; messages lacking 14 days of observable follow-up were treated as right-censored. Pattern 3 was treated as an emergent workflow phenotype rather than a planted abnormality and was defined as a thread containing at least four patient/outbound exchanges spanning at least three days without an intervening office visit. Its prevalence was estimated directly from the generated event history. Patterns 5a and 5b were evaluated as rate-estimation tasks, and Pattern 6 remained descriptive.

This framework distinguishes recovery of deliberately planted abnormalities from reconstruction of workflow phenotypes that can arise naturally from the simulated message process. In particular, a naturally occurring thread that satisfies the Pattern 3 operational definition is counted as an extended thread rather than treated as a false-positive detection solely because it was not deliberately planted.
